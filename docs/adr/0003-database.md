# ADR-003: SQLite для MVP, PostgreSQL для продакшна

- Статус: принято
- Дата: 2026-09-24
- Кто принял: команда проекта

## Контекст

Нагрузка — 30–40 заявок в неделю и до 15 сотрудников. На неделях 3–9 команде нужна база, которую можно поднять
одной командой на ноутбуке и в CI без Docker и без сервера. В продакшне нужны резервное копирование, одновременная
работа нескольких пользователей и разграничение доступа.

## Рассмотренные варианты

1. **Сразу PostgreSQL везде.** Плюсы: одна СУБД. Минусы: каждому разработчику и CI нужен сервер/контейнер.
2. **SQLite везде.** Плюсы: ноль инфраструктуры. Минусы: слабее для одновременной записи, нет ролей в СУБД.
3. **SQLite для MVP и тестов, PostgreSQL в продакшне.** Одна логическая модель в двух файлах схемы.

## Решение

Вариант 3. `db/schema.sql` — SQLite, `db/schema.postgres.sql` — та же модель для PostgreSQL. Переход — в ЗС 10
вместе с CI/CD; до этого SQL в коде пишем без SQLite-специфики, кроме `datetime('now')`.

## Последствия

- \+ `pytest` и демо работают сразу после `pip install`.
- − Две схемы нужно держать синхронными: любое изменение модели — в оба файла в одном PR.
- − Перед переходом на PostgreSQL заменить `datetime('now')` на `now()` и прогнать тесты на PostgreSQL.
