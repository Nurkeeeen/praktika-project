# ADR-001: Выбор модели поставки для проекта «Практика»

- Статус: принято
- Дата: 2026-09-10
- Кто принял: команда проекта (ЛЗ 2)

## Контекст

Проект «Практика» — внутренний сервис университета для карьерного центра (карточка проекта — ЛЗ 1, часть 5).
Команда — 2–4 студента, семестр фиксирован 15 неделями лабораторных, сдача артефактов привязана к календарю курса.
Заказчик — методист карьерного центра, доступен ограниченно (несколько встреч в семестр) и не может на первой встрече
сформулировать все требования — часть уточняется только после показа прототипа.

## Рассмотренные варианты

1. **Predictive (waterfall).** Плюсы: вехи легко синхронизировать с календарём ЛЗ. Минусы: заказчик не может отдать
   все требования на неделе 1–2; риск, что релиз не совпадёт с тем, что нужно методисту.
2. **Чистый Adaptive (Scrum по книге).** Плюсы: гибкость. Минусы: у методиста нет ресурса быть постоянным Product
   Owner с недельными церемониями — доступен раз в 2–3 недели.
3. **Hybrid.** Снаружи — фиксированные контрольные точки по неделям сдачи ЛЗ. Внутри блока — короткие итерации с
   демонстрацией заказчику раз в 2–3 недели, бэклог пересобирается по итогам демо.

## Решение

Вариант 3 — Hybrid.

## Последствия

- \+ Поставка синхронизирована с календарём ЛЗ, промежуточные артефакты есть на каждую лабораторную.
- \+ Бэклог можно менять по итогам демо, не пересобирая план целиком.
- − Нужна дисциплина: заранее зафиксировать, какая неделя ЗС = какая веха, иначе гибридность становится оправданием хаоса.
- − Команде самой нужно предложить методисту ритм демо раз в 2–3 недели.
