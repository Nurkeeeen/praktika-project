## Часть 1. Бизнес-кейс

### 1.1. Проблема

Заявки студентов на практику и предложения работодателей-партнёров карьерный центр собирает вручную — по почте и в Excel-таблице (карточка проекта, ЛЗ 1, часть 5). Студент не видит статус заявки, сроки отчётов о практике никто не отслеживает автоматически, часть писем теряется. Это не «хотелка»: проблема проявляется в измеримых потерях времени персонала и в жалобах студентов, а персональные данные студентов хранятся в почтовых ящиках и файлах без разграничения доступа.

Как это заметно (цифры из карточки проекта — подтвердить у заказчика замером за 2 недели): методист тратит около 4 ч в неделю на сведение заявок [A3]; поток в пик — 30–40 заявок в неделю; «несколько раз в семестр» теряется заявка [A16].

### 1.2. Ценность: для кого, какая метрика, насколько и к какому сроку

| Метрика | Для кого | Сейчас | Цель | Срок | Как измеряем |
|---|---|---|---|---|---|
| Время на сведение заявок | Методист карьерного центра | 4 ч/нед [A3] | ≤ 1 ч/нед | конец весеннего семестра 2027 | самозамер методиста 2 недели до и после |
| Доля заявок с прослеживаемым статусом | Студент, методист | 0 % | 100 % | с запуска (февраль 2027) | GET /stats → tracked_share |
| Потерянные заявки | Студент, работодатель | ≈ 8 в год [A16] | 0 | 2027 год | журнал обращений карьерного центра |
| Отчёты о практике, сданные в срок | Куратор, кафедра | не измеряется | ≥ 90 % | весенний семестр 2027 | GET /reports/overdue; базу замерить на пилоте |

> Честная оговорка: базовое значение для отчётов в срок сейчас никто не считает — сначала замеряем, потом ставим цель. Цель «≥ 90 %» пока является допущением.

### 1.5. Cost of delay

Каждый месяц без системы стоит около 39 903 ₸ времени персонала — немного в деньгах. Сильнее другое: окно запуска привязано к календарю. Если система не готова к началу весеннего семестра 2027 (распределение на практику), следующий пик — только осенью 2027, то есть задержка на 1 месяц в декабре превращается в потерю полугода эффекта. Поэтому приоритет в бэклоге — не «больше функций», а минимальный работающий контур к февралю: подача заявки → статус → маршрутизация → сроки отчёта.

### 1.6. Рекомендация

Рекомендуется вариант В3-С — открытый стек силами студенческой команды: единственный вариант с положительным NPV (180 105 ₸) и ROI +29 % за 3 года, окупаемость — 1,2 года эксплуатации.

Главный вывод, который важнее самой рекомендации: при таком масштабе (30–40 заявок в неделю) ни покупка, ни заказная разработка по рыночной ставке за 3 года не окупаются. Если бы вуз платил подрядчику, рациональным выбором был бы В0. Проект оправдан только как дешёвая сборка на открытом стеке плюс немонетизируемые выгоды: прослеживаемость заявок и вывод персональных данных студентов из почты и Excel.

Условия «идём / не идём» (go / no-go), проверяем до недели 5:

1. Методист подтверждает замером за 2 недели, что сводит заявки не меньше 3 ч/нед (допущение A3). Если экономия ниже 82 % от расчётной — NPV уходит в минус, возвращаемся к В0 и минимальному варианту (общая таблица + форма).
2. ИТ-отдел письменно соглашается на поддержку до 4 ч в месяц и размещение на сервере (A10, A13). Без владельца поддержки система после выпуска команды превращается в риск, а не в актив.
3. Спонсор утверждает бюджет года 0 и годовой бюджет эксплуатации (см. устав).

## Часть 2. Финансовая модель: TCO на 3 года

Модель лежит в двух видах, которые дают одинаковые числа: finance/tco_model.xlsx (LibreOffice Calc / Google Sheets / Excel, все расчёты — формулами от листа «Параметры») и finance/tco_model.py (тот же расчёт в коде, покрыт тестом). Горизонт: год 0 — внедрение (осень 2026, стенд работает 4 месяца [A15]), годы 1–3 — эксплуатация.

### 2.1. Формулы

- Стоимость часа = зарплата × коэффициент начислений / 168 ч → методист 2 157 ₸, разработчик 3 204 ₸.
- Экономия часов в год = (4 − 1) ч × 36 нед + 12 кураторов × 0,5 ч × 50 % × 30 нед + 8 заявок × 3 ч = 222 ч.
- Годовой эффект = часы × ставка методиста = 478 839 ₸; в год 1 — 80 % [A6].
- TCO = Σ затрат годов 0–3 (разработка, лицензии, инфраструктура, перенос данных, обучение, поддержка, вывод из эксплуатации).
- ROI = (Σ выгод − TCO) / TCO.
- NPV = Σ (выгода_t − затраты_t) / (1 + r)^t, r = 16,25 % — базовая ставка НБ РК [S7].
- Окупаемость — момент, когда накопленный поток становится ≥ 0 (линейно внутри года).

### 2.3. Отдельно: то же решение на открытом ПО

Сравниваем В3 (открытый стек) с В2 (проприетарный) при одинаковой трудоёмкости. Разница TCO за 3 года — 4 686 705 ₸, и это целиком лицензии: Windows Server 2025 Standard (16 ядер, $1 176) + SQL Server Standard 2 × 2 ядра (по $3 945) по курсу 445,65 ₸/$ с НДС 16 % [S5, S6, S8]. Это 9,8 годовых эффекта проекта.

Честная оговорка: бесплатная редакция SQL Server Express снимает большую часть лицензии, но имеет ограничения по размеру базы и ресурсам и всё равно требует лицензии Windows Server. Для нашей нагрузки открытый стек (PostgreSQL + Linux) закрывает задачу без лицензионных платежей и без привязки к вендору; решение оформлено в ADR-002.

### 2.5. Допущения

- [A1] Начисления работодателя на ФОТ — коэффициент 1,15 (социальный налог и взносы, укрупнённо).

- [A6] В первый год эксплуатации реализуется 80 % эффекта (адаптация пользователей).
- [A7] Трудоёмкость MVP: 480 ч разработки + 120 ч PM/аналитики (уточняется в ЗС 5–6).
- [A8] Перенос исторических данных из Excel — 16 ч.

- [A11] Битрикс24: 40 ч настройки, 2 ч/мес администрирования; типовая CRM закрывает ~80 % эффекта (нет кабинета студента под наш процесс).

- [A13] Вариант В3-С: труд студенческой команды в году 0 университет не оплачивает (учебный проект), поддержку с года 1 берёт ИТ-отдел по рыночной ставке.
- [A14] Проприетарный стек размещается на том же VPS по модели BYOL; лицензии бессрочные, без Software Assurance; разработка по трудоёмкости как в В3.
- [A15] Эффект начинается с года 1; в году 0 стенд работает 4 месяца (1/3 годовой стоимости инфраструктуры/подписки).
